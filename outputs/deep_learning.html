1. Load, inspect and audit the original images¶

Xiao et al. (2017) describe 60,000 training and 10,000 test images, 28 × 28 pixels each, with ten equally sized categories. Source and label dictionary: https://github.com/zalandoresearch/fashion-mnist. The source repository publishes MD5 fingerprints; SHA-256 fingerprints are also saved for this exact copy. The dataset's MIT notice is retained in data/LICENSE.fashion-mnist.

Headers, lengths, label counts, ranges and exact pixel repetitions are checked before modeling. Pixel equality is not proof that two files represent the same physical garment. We preserve the official benchmark, report cross-partition matches and do not claim a product-independent or duplicate-free evaluation.

def read_images(filename):
    raw = gzip.decompress((DATA / filename).read_bytes())
    magic, n, h, w = struct.unpack(">IIII", raw[:16])
    assert magic == 2051 and (h, w) == (28, 28)
    assert len(raw) == 16 + n * h * w
    return np.frombuffer(raw, dtype=np.uint8, offset=16).reshape(n, h, w).copy()

def read_labels(filename):
    raw = gzip.decompress((DATA / filename).read_bytes())
    magic, n = struct.unpack(">II", raw[:8])
    assert magic == 2049 and len(raw) == 8 + n
    return np.frombuffer(raw, dtype=np.uint8, offset=8).copy()

2. Fixed splits and preprocessing¶

Only the official training set supplies training and validation records: 5,000 / 1,000 per class, chosen with seed 20261119. No test image affects gradient updates, learning-rate choices or epoch selection. Looking at test labels here checks the documented file structure and class counts, not model performance. Original image indices and partition hashes make split identity inspectable.

Pixels become float32 in [0,1] by dividing by 255, with shape N × 1 × 28 × 28. There is no estimated mean/variance, imputation, augmentation or label encoding fit on held-out images. Integer labels become torch.int64. Exact pixel matches are counted across partitions; they are a disclosed evaluation risk.

3. Baseline architecture and the one-variable comparison¶

CNNs fit image inputs because their layers learn visual representations (LeCun et al., 2015). This deliberately small network applies two 3 × 3 convolutions, ReLU activations and 2 × 2 max pooling, followed by a 64-unit hidden layer and ten output logits. Pooling reduces 28 → 14 → 7, so flattening produces 16 × 7 × 7 = 784 values. ReLU introduces nonlinearity; the raw logits feed CrossEntropyLoss, which expects unnormalized class scores and integer labels (PyTorch contributors, n.d.-b). There is no softmax before the loss.

Exactly one major aspect changes: Adam learning rate 0.001 → 0.0003. Adam's default 0.001 is a documented baseline, not an established optimum (PyTorch contributors, n.d.-a). The smaller value tests smaller updates under the same five-epoch budget. Both models have identical architecture, initial weights, training orders, batch size 128, loss and all other optimizer settings. Five epochs and this small width are resource-bounded choices, not tuned hyperparameters. No dropout, scheduler, augmentation, early stopping or validation-based checkpoint selection is used. Both final epoch-five models are evaluated. A single controlled run per configuration tests this setup, not the distribution of results across random seeds.

    digest = hashlib.sha256()
    for key, tensor in state.items():

4. Train both models and record every epoch¶

Gradient tracking is enabled only for training; evaluation uses model.eval() and torch.inference_mode(). Loss totals are weighted by sample count, so the last shorter batch is not given the weight of a full batch. Epoch training metrics are online measurements while parameters change; validation metrics are calculated after each epoch at fixed weights. They are therefore not strictly identical measurement conditions.

Both configurations load the exact same initial state. Each epoch uses the same seeded permutation for both runs, recorded with SHA-256; Adam is new for each run. Deterministic algorithms and explicit seeds reduce variation on this CPU/software stack, but do not guarantee identical results on different hardware or PyTorch releases (PyTorch contributors, n.d.-c).

loss_fn = nn.CrossEntropyLoss()
history, controls, durations, trained = [], {}, {}, {}

def evaluate(model, x, y, batch_size=512):
    model.eval()
    total_loss, correct = 0.0, 0
    logits_parts = []
    with torch.inference_mode():
        for start in range(0, len(y), batch_size):
            xb, yb = x[start:start + batch_size], y[start:start + batch_size]
            logits = model(xb)
            total_loss += loss_fn(logits, yb).item() * len(yb)
            correct += int((logits.argmax(1) == yb).sum())
            logits_parts.append(logits)
    return total_loss / len(y), correct / len(y), torch.cat(logits_parts)

5. Evaluate both final models on the official test set¶

Accuracy is the share of correct top-one labels and is meaningful for this balanced ten-class benchmark. A confusion matrix and per-class recall expose mistakes hidden by that overall average. Macro-F1 averages each class's precision/recall balance with equal class weight; zero denominators receive zero (scikit-learn developers, n.d.). Cross-entropy also considers the scores assigned to the true labels (PyTorch contributors, n.d.-b). Definitions are implemented explicitly below. Softmax scores sum to one but are not certified confidence or calibrated probabilities.

Test evaluation occurs only after both models finish training; no learning rate or checkpoint is chosen using test performance. The experiment retains all predictions and both confusion matrices, not only the better-looking outcome. No statistical significance or multi-seed robustness is claimed.

def classification_metrics(y_true, y_pred):
    cm = np.zeros((10, 10), dtype=np.int64)
    np.add.at(cm, (y_true, y_pred), 1)
    tp = np.diag(cm).astype(float)
    precision = np.divide(tp, cm.sum(0), out=np.zeros(10), where=cm.sum(0) != 0)
    recall = np.divide(tp, cm.sum(1), out=np.zeros(10), where=cm.sum(1) != 0)
    f1 = np.divide(2 * precision * recall, precision + recall,
                   out=np.zeros(10), where=(precision + recall) != 0)
    return cm, precision, recall, f1

Limitations, responsible use and next steps¶

Only the learning rate was varied; depth, training duration, initialization and dataset choice were not experimentally optimized. One paired seed and five epochs cannot establish which setting works best generally. No exact pixel matches were found, but near-duplicate products or shared styles are not ruled out; a single catalog and 28 × 28 grayscale preprocessing limit real-world transfer. Neither official partition proves separation by garment identity. Uncertainty across seeds, calibration, new-retailer performance and demographic fairness were not tested.

The intended use is learning and benchmark comparison. A mislabel could place a seller's product in the wrong search category and reduce its visibility. Categories/styles absent from this catalog may be served poorly; class balance does not establish fair treatment of sellers or customers. No demographic attributes are provided, so none are inferred. Retain human correction and audit performance on diverse, permissioned product images before any retail use; document intended uses and limitations, following model-reporting guidance (Mitchell et al., 2019). Do not repurpose this model for judging people.

Next, repeat the same paired comparison across seeds and report variability, audit product-identity overlap if identifiers become available, and obtain an independent color-photo dataset with permission. Compare longer fixed training budgets separately from learning-rate changes; do not change multiple factors and attribute all gains to one. Keep any new test set separate from tuning.

Notebook summary¶

This supervised image-classification experiment used all 70,000 real Fashion-MNIST clothing images, with 50,000 for training, 10,000 for validation and the official 10,000-image test set. Two identical PyTorch CNNs started from the same weights and saw the same shuffled batches for five epochs; only Adam's learning rate changed from 0.001 to 0.0003. The baseline achieved 87.29% test accuracy and 0.8705 macro-F1, compared with 84.63% and 0.8430 for the smaller-rate model, a signed accuracy change of -2.66 percentage points. The first baseline error was test image 12, labeled Sneaker but predicted Bag; it illustrates why aggregate accuracy does not guarantee a correct clothing label for each image. One seed, five epochs, untested garment-identity overlap and a single retailer's tiny grayscale images limit broader conclusions, so neither result establishes production readiness or a universally better learning rate.
